Establish **isolation** before the worktree's first build, test, migration, or dev server. All processes read/write only its own **footprint** (databases, containers, ports, untracked overrides), never another checkout's. Apply each step whenever the project has the named resource, even for read-only changes.

1. **Untracked config**: Copy missing build/run files (`.env`, `local.properties`, signing/service configs) from the main checkout's untracked files; preserve exact contents. If denied, ask the user to run `! cp <main-checkout>/<file> <worktree>/<file>`. Create/complete `.worktreeinclude` with every required untracked file; commit it with the change unless ignored or project instructions say otherwise. Done when the project builds and starts without missing-file errors.
2. **Databases**: Create separate app/test databases named after the worktree; migrate both. Trace each consumer's env source (dev server, migration tool, test runner); point it at its database via its untracked override (`.env.local`, `.env.test.local`). If only tracked config is read, edit it and mark `git update-index --skip-worktree`. If scripts bind one container per database, give each new database its own container/free port. Leave existing databases untouched. Done when all three consumers resolve to this worktree's databases.
3. **Ports**: Assign every port-binding process (dev server, bundler, emulator bridge) a free port within project requirements (web: 3000–3100, OAuth callback range). Point every configured localhost URL (`.env.example` or equivalent) at these ports via the untracked override. Start the project's dev command on them. Done when its output shows those ports.

Done when every applicable step meets its completion criterion.
