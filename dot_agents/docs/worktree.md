Set the worktree up in **isolation** before its first build, test run, migration, or dev server: from then on, everything it runs reads and writes only its own **footprint** (its databases, containers, ports, and untracked overrides), never the main checkout's or a concurrent worktree's. Each step applies when the project has what it names, whatever the change touches: a project with a database gets step 2 even for a change that only reads.

1. **Untracked config**: Copy from the main checkout every untracked file the project needs to build or run (`.env`, `local.properties`, signing or service config files), when missing, and keep each exactly as copied; when the copy is denied, ask the user to run `! cp <main-checkout>/<file> <worktree>/<file>`. Make the project's `.worktreeinclude` list every such file, creating or completing it; commit it with the current change unless git ignores it or the project's instructions say otherwise. Done when the project builds and starts without a missing-file error.
2. **Databases**: Give this worktree its own app database and its own test database, named after the worktree and each migrated. Trace which env file each consumer reads (dev server, migration tool, test runner) and point each at its database through that consumer's untracked override (`.env.local`, `.env.test.local`); when a consumer reads only a tracked file, edit it and mark it `git update-index --skip-worktree`. When the project's database script binds one container to one database, give each new database its own container on a free port. Existing databases stay untouched. Done when the dev server, migrations, and test runner each resolve to this worktree's databases.
3. **Ports**: Give every local process that binds a port (dev server, bundler, emulator bridge) a free one, inside the range the project requires (web: 3000–3100, the OAuth callback range). Point every localhost URL the project's config lists (`.env.example` or equivalent) at those ports through the untracked override. Start the project's dev command on them. Done when its output shows those ports.

Done when every step that applies has met its bar.
